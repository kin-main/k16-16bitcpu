# k16 — 16-bit RISC CPU

FPGA向けに設計された、シンプルで高クロック動作を目指す 16-bit RISC CPU（2段パイプライン）の Verilog-HDL 実装です。

KISS 原則（Keep It Simple, Stupid）に基づき、必要最小限のシンプルな回路構成で、効率と設計の見通しの良さを追求しています。
命令とデータを単一のアドレス空間・単一のメモリポートで共有するノイマン型（von Neumann）アーキテクチャを採用し、メモリ空間内に MMIO（UART I/O）を統合しています。
RTL 設計などの開発工程では、AI を積極的に活用しています。

## 2. レジスタ構成（Register File）

| レジスタ | 名前 | 役割・動作 |
| --- | --- | --- |
| **`r0`** | Zero Register | 常に `0x0000` を出力。書き込みは無視 |
| **`r1`〜`r12**` | 汎用レジスタ（GPR） | 16-bit 演算・データ処理用 |
| **`r13`** | 拡張バイトレジスタ | 24-bit メモリアクセス時の上位8-bit（`[23:16]`）を `r13[7:0]` で送受信 |
| **`r14`** | フラグレジスタ | ALU フラグ `{13'b0, N, C, Z}` を読み出し専用で出力。書き込みは無視 |
| **`r15`** | プログラムカウンタ（PC） | 実行中の命令アドレス。明示的な書き込みでジャンプ（分岐） |

## 3. メモリアーキテクチャと MMIO（UART I/O）

### 3.1. ノイマン型単一バス調停

k16 は命令メモリとデータメモリを分離せず、単一の16-bit アドレス空間と単一の24-bit 幅メモリポートを使用します。
メモリポートは以下の信号で構成されます。

* **`mem_addr`**: メモリアドレス
* **`mem_wdata`**: メモリ書き込みデータ
* **`mem_rdata`**: メモリ読み出しデータ
* **`mem_we`**: メモリ書き込みイネーブル

命令フェッチと Load/Store（RAM・MMIO アクセス）は、このバスを共有します。
1サイクルに使用できるメモリポートは1系統のみであるため、次のアクセスが競合した場合はデータアクセスを優先します。

* 次命令のフェッチ
* 実行中の命令によるデータアクセス、または MMIO アクセス

条件が成立した Load/Store 命令の実行サイクルでは、次サイクルの IR に1サイクルのバブル（NOP）を挿入し、PC を保持します。
次サイクルでバスが解放されると、命令を再フェッチします。
したがって、Load/Store 命令1つにつき、実行時間が1サイクル余分にかかります。

### 3.2. メモリマップと MMIO レジスタ一覧

| アドレス | 名称 / シンボル | 役割・動作 |
| --- | --- | --- |
| **`0x0000`〜`0xFEFF**` | メイン RAM | プログラム命令コードおよび通常データ領域 |
| **`0xFF00`** | `UART_DATA` | Write（Store）: 下位8-bitを送信データとして書き込み、UART TX を開始。<br>

<br>Read（Load）: 受信データ（8-bit）を読み出し、`rx_ready` をクリア |
| **`0xFF01`** | `UART_STATUS` | Read（Load）。bit 0 = `tx_busy`（1: 送信中、0: アイドル）、bit 1 = `rx_ready`（1: 受信データあり） |
| **`0xFF02`** | `UART_BAUD` | 予約領域。ボーレート設定用 |

## 4. 命令フォーマット（Instruction Format）

全命令は24-bit 固定長で、最上位3-bitに条件実行フィールド `cond[23:21]` を備えます。

### 4.1. レジスタ間演算命令（`op = 00`）

```text
 23       21 20 19 18      15 14      11 10       7 6       3 2       0
+-----------+-----+----------+----------+----------+----------+---------+
|  cond (3) | 00  |  rd (4)  |  rs1 (4) |  rs2 (4) |  unused  |  funkt  |
+-----------+-----+----------+----------+----------+----------+---------+

```

### 4.2. レジスタ即値演算命令（`op = 01`）

```text
 23       21 20 19 18      15 14      11 10                     3 2       0
+-----------+-----+----------+----------+---------------------+---------+
|  cond (3) | 01  |  rd (4)  |  rs (4)  |     imm (8-bit)     |  funkt  |
+-----------+-----+----------+----------+---------------------+---------+

```

### 4.3. ロード / ストア命令（`op = 11`）

```text
 23       21 20 19 18      15 14      11 10                     2 1       0
+-----------+-----+----------+----------+---------------------+-----------+
|  cond (3) | 11  |  rd (4)  | base (4) |     imm (9-bit)     |   funkt   |
+-----------+-----+----------+----------+---------------------+-----------+

```

## 5. 命令セット（Instruction Set）

### 5.1. 条件実行フィールド（`cond[23:21]`）

| cond | アセンブリ | 実行条件 | 説明 |
| --- | --- | --- | --- |
| `000` | AL | 常に実行 | Always |
| `001` | NE | Z == 0 | ゼロでない（Not Equal） |
| `010` | NC | C == 0 | キャリーなし（No Carry） |
| `011` | PL | N == 0 | 正またはゼロ（Plus） |
| `100` | NV | 実行しない | Never / NOP |
| `101` | EQ | Z == 1 | ゼロ（Equal） |
| `110` | CS | C == 1 | キャリーあり（Carry Set） |
| `111` | MI | N == 1 | 負数（Minus） |

### 5.2. ALU 演算（`funkt[2:0]`, `op = 00 / 01`）

| funkt | 演算 | 動作 | 更新対象フラグ |
| --- | --- | --- | --- |
| `000` | NAND | `rd = ~(A & B)` | Z, N |
| `001` | OR | `rd = A | B` | Z, N |
| `010` | AND | `rd = A & B` | Z, N |
| `011` | XOR | `rd = A ^ B` | Z, N |
| `100` | ADD | `rd = A + B` | Z, C, N |
| `101` | SUB | `rd = A - B`（`A + ~B + 1`） | Z, C, N |
| `110` | ADC | `rd = A + B + C` | Z, C, N |
| `111` | SHR | `rd = A >> 1`（論理右シフト、`C = A[0]`） | Z, C, N |

#### 5.2.1. フラグ更新仕様（Z / C / N）

フラグの更新規則は以下のとおりです。

* フラグ更新対象は、条件成立した ALU レジスタ演算（`op = 00`）および ALU 即値演算（`op = 01`）のみです。
* 命令はデコード後に実行段へ入り、ALU の組み合わせ演算結果を受けて、実行サイクルのクロック立ち上がりで Z/C/N を更新します。
* 更新後の Z/C/N は、次の命令の条件判定（`cond`）に使用されます。
* 条件不成立命令、Load/Store（`op = 11`）、および `r15`（PC）宛ての ALU 演算ではフラグを更新しません。
* 非同期リセット時は `Z = 0, C = 0, N = 0` に初期化されます。

| フラグ | 更新規則 |
| --- | --- |
| **Z** | `Z = (result == 0)` |
| **N** | `N = result[15]` |
| **C（ADD / SUB / ADC）** | `temp[16]`。ただし、SUB は17-bit減算の折り返しが入るため、`A < B` で `C = 1`（ボロー発生）。x86 流に準拠 |
| **C（SHR）** | シフトアウトされる `A[0]` |
| **C（NAND / OR / AND / XOR）** | 保持（更新しない） |

`r14` はフラグの読み出し専用レジスタです。読み出し値は `{13'b0, N, C, Z}` で、書き込みは無視されます。

### 5.3. ロード / ストア（`funkt[1:0]`, `op = 11`）

| funkt | 命令 | 動作 | 24-bit データ転送 |
| --- | --- | --- | --- |
| `00` | LD（加算） | `rd = mem[base + imm]` | `rd <= mem[15:0]`、`r13[7:0] <= mem[23:16]` |
| `01` | LD（減算） | `rd = mem[base - imm]` | `rd <= mem[15:0]`、`r13[7:0] <= mem[23:16]` |
| `10` | ST（加算） | `mem[base + imm] = {r13[7:0], rd}` | `mem[15:0] <= rd`、`mem[23:16] <= r13[7:0]` |
| `11` | ST（減算） | `mem[base - imm] = {r13[7:0], rd}` | `mem[15:0] <= rd`、`mem[23:16] <= r13[7:0]` |

## 10. 旧実装のバグ修正履歴（2026-09）

初版のパイプライン制御には、以下の不具合がありました。これらは旧実装に対して修正されています。

### 10.1. Load ストール時の命令取りこぼし

* **問題**: `cpu.v` において、Load 実行サイクルに IF/ID をホールドした際、前サイクルにフェッチ済みの L+2 命令が廃棄されていました。
* **修正**: `pend_inst` / `pend_valid` レジスタを追加し、フェッチ済み命令を退避して翌サイクルの IF/ID へ復帰させるように変更しました。
ただし、前サイクルがバス占上の場合は退避せず、`pc_hold` による再フェッチで吸収します。

### 10.2. 分岐フラッシュの漏れ

* **問題**: 初期実装ではフラッシュが1サイクル分のみだったため、以下の問題が発生していました。
* 分岐直後のパス命令（J+1）が実行される
* J+3 が取り込まれる


* **修正**: 以下の2段階フラッシュへ変更しました。
1. 分岐成立サイクルに ID/EX を NOP 化（`pc_write_now`）
2. 翌サイクルに IF/ID を NOP 化（`branch_flush_q`）
これにより、分岐ペナルティは3サイクルとなります。



### 10.3. r14（フラグ）読み出しの1命令遅れ

* **問題**: ID ステージでフラグをキャプチャしていたため、直前の命令によるフラグ更新が反映されませんでした。
* **修正**: EX ステージに、以下のライブ読み出し用 MUX を追加しました。
* `ex_rddata_a`
* `ex_rddata_b`
これにより、最新の ALU フラグ `{nf, cf, zf}` を参照できるようになりました。



### 10.4. UART 送信直後の `tx_busy` 誤報告

* **問題**: `tx_start` が busy 判定に含まれていなかったため、送信ストア直後にステータスを読み取ると、UART がアイドル状態として報告されていました。
* **修正**:
```verilog
assign tx_busy = (tx_state != TX_IDLE) | tx_start;

```


これにより、TX 開始サイクルから `tx_busy` が正しく 1 になります。

### 10.5. UART 送信データの破壊

* **問題**: `tx_data` がバスの組み合わせ値を直接参照していたため、UART が1サイクル後にデータをラッチする時点でバス内容が変化し、誤ったバイトが送信される問題がありました。
* **修正**: `mmio.v` に `tx_hold` レジスタを追加し、書き込みサイクルで送信データをラッチするように変更しました。
**処理の流れ:**
```text
MMIO Write
    │
    ▼
tx_hold にデータをラッチ
    │
    ▼
UART TX 開始
    │
    ▼
tx_hold の値を送信

```


これにより、バスの状態変化による送信データの破壊を防止しました。

## 11. 設計上の特徴

k16 は、以下の設計方針に基づいています。

* 16-bit RISC
* 24-bit 固定長命令
* 2段パイプライン
* ノイマン型アーキテクチャ
* 単一メモリポート
* 24-bit メモリデータ幅
* 全命令条件実行
* フォワーディングによる RAW ハザード回避
* 分岐フラッシュ
* Load/Store 時のバス調停
* MMIO UART
* Verilog-HDL による FPGA 実装
* Python によるサイクル精度検証

設計の複雑化を避けながら、FPGA 上で実際に動作する CPU として必要なパイプライン制御、ハザード処理、メモリ調停、MMIO までを実装することを目的としています。
