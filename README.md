k16 16-bit RISC CPU

FPGA向けに設計された、シンプルで高クロック動作を目指す 16-bit RISC CPU（2段パイプライン） のVerilog-HDL実装です。

KISS原則（Keep It Simple, Stupid） に基づき、必要最小限のシンプルな回路構成で最大の効率と見通しの良さを実現しています。

命令とデータを単一のアドレス空間・単一のメモリポートで共有する ノイマン型（von Neumann）アーキテクチャ を採用し、メモリ空間内に MMIO（UART I/O） を統合しています。

3. メモリアーキテクチャ & MMIO（UART I/O）

3.1 ノイマン型単一バス調停

k16は命令メモリとデータメモリを分離せず、単一の16-bitアドレス空間・単一の24-bit幅メモリポートを使用します。

メモリポートは以下の信号で構成されます。

mem_addr
mem_wdata
mem_rdata
mem_we

命令フェッチとLoad/Store（RAM・MMIOアクセス）の両方がこのバスを共有します。

1サイクルに使用できるメモリポートは1系統のみであるため、

* 次命令のフェッチ
* 現在実行中の命令によるデータ/MMIOアクセス

が競合した場合、データアクセスを優先します。

条件成立したLoad/Store命令の実行サイクルでは、次サイクルのIRに1サイクルのバブル（NOP）が挿入され、PCは進めずに保持されます。

次サイクルでバスが解放され次第、正しく命令を再フェッチします。

したがって、Load/Store命令1つにつき実行時間が1サイクル余分にかかります。

⸻

3.2 メモリマップ & MMIOレジスタ一覧

アドレス	名称 / シンボル	役割・動作
0x0000〜0xFEFF	メインRAM	プログラム命令コードおよび通常データ領域
0xFF00	UART_DATA	Write（Store）: 下位8-bitを送信データとして書き込み、自動でUART TX開始。Read（Load）: 受信データ（8-bit）を読み出し、rx_ready をクリア
0xFF01	UART_STATUS	Read（Load）。bit 0 = tx_busy（1: 送信中、0: アイドル）、bit 1 = rx_ready（1: 受信データあり）
0xFF02	UART_BAUD	予約。ボーレート設定用

5. 命令一覧（Instruction Set）

5.1 条件実行フィールド（cond[23:21]）

cond	アセンブリ	実行条件	説明
000	AL	常に実行	Always
001	NE	Z == 0	ゼロでない（Not Equal）
010	NC	C == 0	キャリーなし（No Carry）
011	PL	N == 0	正またはゼロ（Plus）
100	NV	実行しない	NOP（No Operation）
101	EQ	Z == 1	ゼロ（Equal）
110	CS	C == 1	キャリーあり（Carry Set）
111	MI	N == 1	負数（Minus）

5.2 ALU演算（funkt[2:0], op = 00 / 01）

funkt	演算	動作説明	フラグ変化
000	NAND	rd = ~(A & B)	Z, N
001	OR	rd = A | B	Z, N
010	AND	rd = A & B	Z, N
011	XOR	rd = A ^ B	Z, N
100	ADD	rd = A + B	Z, C, N
101	SUB	rd = A - B（A + ~B + 1）	Z, C, N
110	ADC	rd = A + B + C	Z, C, N
111	SHR	rd = A >> 1（論理右シフト、C = A[0]）	Z, C, N

⸻

5.3 ロード / ストア（funkt[1:0], op = 11）

funkt	命令	動作説明	24-bitデータ転送
00	LD（加算）	rd = mem[base + imm]	rd <= mem[15:0]、r13[7:0] <= mem[23:16]
01	LD（減算）	rd = mem[base - imm]	rd <= mem[15:0]、r13[7:0] <= mem[23:16]
10	ST（加算）	mem[base + imm] = {r13[7:0], rd}	mem[15:0] <= rd、mem[23:16] <= r13[7:0]
11	ST（減算）	mem[base - imm] = {r13[7:0], rd}	mem[15:0] <= rd、mem[23:16] <= r13[7:0]

8. バグ修正履歴（2026-09）

初版のパイプライン制御に以下の不具合があり、修正しました。

8.1 Loadストール時の命令取りこぼし

問題

cpu.v において、Load実行サイクルにIF/IDをホールドした際、前サイクルにフェッチ済みの L+2命令 が廃棄されていました。

修正

pend_inst / pend_valid レジスタを追加し、フェッチ済み命令を退避して翌サイクルのIF/IDへ復帰させるように変更しました。

ただし、前サイクルがバス占有の場合は退避せず、pc_hold による再フェッチで吸収します。

⸻

8.2 分岐フラッシュの漏れ

問題

初期実装ではフラッシュが1サイクル分のみだったため、

* 分岐直後のパス命令（J+1）が実行される
* J+3が取り込まれる

という問題が発生していました。

修正

以下の2段階フラッシュへ変更しました。

1. 分岐成立サイクルに ID/EX をNOP化（pc_write_now）
2. 翌サイクルに IF/ID をNOP化（branch_flush_q）

これにより、分岐ペナルティは3サイクルとなります。

⸻

8.3 r14（フラグ）読み出しの1命令遅れ

問題

IDステージでフラグをキャプチャしていたため、直前命令によるフラグ更新が反映されませんでした。

修正

EXステージで、

{nf, cf, zf}

をライブ読み出しするMUX、

ex_rddata_a
ex_rddata_b

を追加しました。

これにより、最新のALUフラグを参照できるようになりました。

⸻

8.4 UART送信直後の tx_busy 誤報告

問題

tx_start が busy の判定に含まれていなかったため、送信ストア直後にステータスを読み取ると、UARTがアイドル状態として報告されていました。

修正

以下のように変更しました。

assign tx_busy = (tx_state != TX_IDLE) | tx_start;

これにより、TX開始サイクルから tx_busy が正しく1になります。

⸻

8.5 UART送信データの破壊

問題

tx_data がバスの組み合わせ値を直接参照していたため、UARTが1サイクル後にデータをラッチする時点でバス内容が変化し、誤ったバイトが送信される問題がありました。

修正

mmio.v に tx_hold レジスタを追加し、書き込みサイクルで送信データをラッチするように変更しました。

MMIO Write
    ↓
tx_hold にデータをラッチ
    ↓
UART TX開始
    ↓
tx_hold の値を送信

これにより、バスの状態変化による送信データ破壊を防止しました。

⸻

9. 設計上の特徴

k16は以下の方針で設計されています。

* 16-bit RISC
* 24-bit固定長命令
* 2段パイプライン
* ノイマン型アーキテクチャ
* 単一メモリポート
* 24-bitメモリデータ幅
* 全命令条件実行
* フォワーディングによるRAWハザード回避
* 分岐フラッシュ
* Load/Store時のバス調停
* MMIO UART
* Verilog-HDLによるFPGA実装
* Pythonによるサイクル精度検証

設計の複雑化を避けながら、FPGA上で実際に動作するCPUとして必要なパイプライン制御・ハザード処理・メモリ調停・MMIOまでを実装することを目的としています。
